# Custom Sandbox Tools

Self-contained, fail-closed replacement for the four `@langchain/community`
tools we used to depend on:

| Replaces | Lives in |
| --- | --- |
| `ShellTool` | [`shell-tool.ts`](./shell-tool.ts) |
| `FileManagementToolkit` | [`file-tools.ts`](./file-tools.ts) |
| `RequestsToolkit` | [`http-tools.ts`](./http-tools.ts) |
| `SQLDatabaseToolkit` | [`sql-tools.ts`](./sql-tools.ts) |

Built on `@langchain/core/tools` `tool()` + `zod` schemas; designed to drop
straight into `createReactAgent({ llm, tools: getAllTools(config) })`.

## Quick start

```ts
import { getAllTools } from "./base/tools/index.js";

const tools = getAllTools({
    // Omit the `shell` key entirely to leave shell access off.
    shell: {
        allowedCommands: ["git", "ls", "cat", "npm"],
        cwd: "/srv/repo",
    },
    file: { rootDir: "/srv/repo", readOnly: false },
    http: { allowedHosts: ["api.example.com"] },
    sql:  { connectionString: ":memory:", allowedTables: ["users"] },
});
```

`upsertMemoryTool` (project-internal) is always included.

## Cross-cutting guarantees

Every tool follows the same contract:

- **Explicit config, no allow-everything defaults.** Construction throws on
  missing required fields.
- **No uncaught exceptions.** Errors are caught and returned as strings
  prefixed `[<tool>] error:` so the agent loop stays alive.
- **Structured logging.** Each call emits one JSON line per event
  (`event: "complete" | "error" | "init"`) to stdout/stderr.
- **Timeouts via `AbortSignal.timeout`.** Default 15 s; configurable per tool.
- **Output truncation.** All tool results are capped (default 6 KB) with an
  explicit `[truncated: ...]` marker so the LLM never sees a silent partial
  read.
- **No new npm dependencies.** All four tools use Node 24 built-ins
  (`node:child_process`, `node:fs/promises`, `node:dns/promises`,
  `node:net`, `node:sqlite`) plus `@langchain/core/tools` and `zod`.

## `shell-tool.ts`

Whitelist-only, argv-tokenised (no shell).

```ts
import { createShellTool } from "./base/tools/shell-tool.js";

const shell = createShellTool({
    allowedCommands: ["git", "ls", "cat", "npm"],
    cwd: "/srv/repo",
    timeoutMs: 15_000,         // default
    outputLimitBytes: 6144,    // default
});
```

| Config | Type | Default | Notes |
| --- | --- | --- | --- |
| `allowedCommands` | `string[]` | `["git", "ls", "cat", "npm"]` | First argv token must be in this list. |
| `cwd` | `string` | `process.cwd()` | Working dir passed to `execFile`. |
| `timeoutMs` | `number` | `15000` | Aborts the subprocess. |
| `outputLimitBytes` | `number` | `6144` | Per-stream (stdout/stderr) cap. |

**Rejection rules** (no execution, error string returned):

- empty / whitespace-only command
- first token not in `allowedCommands`
- command contains any of: `;`, `&&`, `||`, `|`, `` ` ``, `$(`, `>`, `<`

Returns `stdout`, `stderr` (if any), and the numeric exit code. Non-zero exit
is *data*, not an error.

**Limitations:**

- The metacharacter list is a blocklist, not a parser — clever encodings
  (e.g. UTF-8 tricks) are not analysed. Keep the whitelist small.
- `cd`/shell-builtins are unavailable because there is no shell.

## `file-tools.ts`

Siblings: `readFile`, `writeFile`, `listDirectory`, `deleteFile`.

```ts
import { createFileTools } from "./base/tools/file-tools.js";

const fileTools = createFileTools({
    rootDir: "/srv/repo",      // absolute; throw at construction otherwise
    readOnly: false,           // default false
    maxFileSizeBytes: 1_048_576, // default 1 MB
    outputLimitBytes: 6144,     // default
});
// or read-only: returns [readFile, listDirectory] only
const ro = createFileTools({ rootDir: "/srv/repo", readOnly: true });
```

**Containment model (critical):**

1. `path.resolve(rootDir, requestedPath)` is computed.
2. `fs.realpath` is applied so symlinks cannot escape. If the target does
   not exist (write to a new file), the parent dir is canonicalised instead.
3. The canonical path is verified to be `rootDir` itself or to start with
   `rootDir + path.sep`.
4. Otherwise, rejected with `path "<x>" escapes the sandbox root "<y>": it
   resolves to "<z>"`.

**`readOnly: true` omits `writeFile` and `deleteFile` entirely** — not just
"disabled" but not constructed. Callers can introspect via the returned
`StructuredTool[]`.

**Limitations:**

- Single root per `FileTools` instance. Build multiple instances for
  multiple sandboxes.
- No file locking; concurrent writes can interleave.

## `http-tools.ts`

One tool: `httpFetch`.

```ts
import { createHttpTools } from "./base/tools/http-tools.js";

const http = createHttpTools({
    allowedHosts: ["api.example.com", "internal.svc.cluster.local"],
    timeoutMs: 10_000,           // default 15000
    maxResponseBytes: 6144,      // default
});
```

**SSRF guard (runs before any network call):**

1. URL parsed; `protocol` must be `http:` or `https:`.
2. `hostname` must match `allowedHosts` exactly or as a subdomain suffix
   (`api.example.com` allows `api.example.com` and `x.api.example.com`).
3. `dns.lookup` resolves every A/AAAA record; any private/loopback/
   link-local/CGNAT IPv4 (see ranges in source) or `::1`/ULA/link-local/IPv4-
   mapped IPv6 address rejects the request — DNS-rebind protection.
4. `redirect: "manual"` — 3xx responses are surfaced with the `Location`
   header, not followed (a 302 can point at a private IP).

**No auth.** Per design decision, the tool does not special-case any
authorisation header. Callers must not put secrets in `headers` and rely on
this tool to be safe; the `allowedHosts` list is a network/SSRF constraint,
not an authorisation boundary.

**Limitations:**

- No streaming uploads; `jsonBody` is serialised once and sent.
- No cookie jar, no per-host connection pooling, no HTTP/2 tuning. The tool
  uses Node's native `fetch` as-is.
- Large responses are cut at `maxResponseBytes` mid-stream; the remainder is
  never read.

## `sql-tools.ts`

Siblings: `listTables`, `describeTable`, `runQuery`. SQLite-only via the
built-in `node:sqlite` (Node 22.5+/24).

```ts
import { createSqlTools } from "./base/tools/sql-tools.js";

const sqlTools = createSqlTools({
    connectionString: ":memory:",         // or a file path
    allowedTables: ["users", "orders"],   // optional
    maxRows: 200,                          // default
    timeoutMs: 15_000,                     // accepted; see limitations
    outputLimitBytes: 6144,                // default
});
```

**`runQuery` read-only enforcement** — all four must pass:

1. After stripping `/* … */` and `-- …` comments + whitespace, the statement
   must start with `SELECT` or `WITH` (case-insensitive).
2. No semicolon followed by more non-whitespace (blocks stacked statements;
   a trailing `;` is tolerated).
3. No write/DDL/session keywords anywhere in the *original* SQL:
   `INSERT UPDATE DELETE DROP ALTER CREATE TRUNCATE GRANT REVOKE EXEC
   EXECUTE REPLACE MERGE CALL SET`.
4. Auto-appends `LIMIT <maxRows>` if the query has no `LIMIT` clause.

Every successful execution runs inside `BEGIN … ROLLBACK` (always rolled
back, even on success). This is defence in depth: even if a check is
bypassed, no state mutation can persist.

**Known limitations (call these out, don't paper over them):**

- **Keyword check, not a parser.** A keyword inside a string literal
  triggers a false positive. `SELECT * FROM users WHERE name = 'DROP'`
  is rejected by design. A future iteration could add `node-sql-parser`
  for AST-level validation, but that introduces a new dependency and does
  not handle CTEs that mutate state in all dialects.
- **`runQuery` is not table-scoped.** `allowedTables` filters
  `listTables`/`describeTable` only. A user with a working `runQuery` can
  reference any table by name; protection is via the keyword/prefix guard
  and the read-only transaction, *not* via the table list. If you need
  per-table isolation, parse the SQL and reject references to tables not
  in the allow-list.
- **`timeoutMs` is not enforced.** `node:sqlite` is synchronous, so a
  single SQL call cannot be preempted on the same thread. The value is
  accepted for config parity but is currently decorative. Read-only
  queries against local SQLite are typically fast.
- **SQLite-only.** For Postgres/MySQL, swap the `DatabaseSync` driver
  (`prepare().all()` translates directly) — the rest of the file stays
  the same.
- **Production deployment must use a DB role with `SELECT`-only grant.**
  The in-process keyword/prefix check is a backstop, not a guarantee.
  Defense-in-depth lives in the DB itself.

## Testing

```bash
cd agent
npm test            # runs the whole suite (node:test)
npm run typecheck   # tsc --noEmit
```

Tests are co-located next to the source as `*.test.ts`. They use
`node:test` + `node:assert/strict` — no extra deps.

## Notes

- TypeScript: project tsconfig has `strict: false` for historical reasons.
  The new tool files are written defensively regardless, but flipping
  `"strict": true` in `agent/tsconfig.json` is a worthwhile follow-up.
- Logging: every tool call emits a single JSON line per event to
  stdout/stderr. Pipe these to your log aggregator for audit; they are
  intentionally greppable.
- Back-compat: `tools/index.ts` still exports a `tools = [upsertMemoryTool]`
  flat list for the existing graph nodes (`call-llm.ts`, `call-tool.ts`).
  New code should prefer `getAllTools(config)`.
